# Market ideas ledger

The dedupe record for the `/market-ideas` dev skill (`.claude/commands/market-ideas.md`). Every idea the market has offered PAN Wizard gets one row with a stable id, a status and the fact that decided it, so a later scan can tell "new" from "seen" and cannot re-propose a rejected idea without a new fact. Rows are appended, never deleted; a status change carries the date. This file lives under `docs/specs/` so it may name model versions and cite dated releases.

Companion documents: the dimension-level peer read is `docs/COMPARISON.md` ("Direct Peers"); the standing-and-claims audits are `docs/ECOSYSTEM-REVIEW-*.md` and `/reality-check`; the sized queues this ledger points at are `docs/specs/market-delta-*-superplan.md` and `docs/specs/market-ideas-*.md`.

## Rules

- **One row per concept**, not per wording or per vendor. `maxTurns` and "turn caps on subagents" are one row; the same idea shipped by two peers is one row with two sources.
- **A SKIP or DECLINED row is re-opened only by a new fact** that overturns the recorded reason. Name the fact in the Decision column with its date.
- **A WATCH row names its trigger** and is re-checked every run — against the market **and** against `CHANGELOG.md`, because PAN's own releases fire triggers too (MI-009 did).
- **ADOPTED / ADAPTED rows name the version or commit.** A status column is a claim; the skill re-verifies it by grep before trusting it.
- **No filesystem-derived counts** in this file (the counts rule in `CLAUDE.md`). State the class and the command.
- **No "no competitor does this."** Say "not found in the roster on `<date>`".

Statuses: OPEN · ADOPTED · ADAPTED · WATCH · SKIP · DECLINED · BLOCKED (definitions in the skill's Appendix C). An OPEN row names its queue item (`M<n>` in `market-ideas-2026-09.md`).
