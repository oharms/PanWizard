### (b) Model-version-agnostic sweep (user-directed)

Independent of the audit ledger: the user asked for hardcoded model-version gates to stop shipping. Version-pinned claims in shipped runtime content (`commands/`, `agents/`, `pan-wizard-core/`) and in the live docs were replaced with **capability** phrasing ("a model with a 1M-context window", "thinking-capable models", "models that support prompt caching"), with the **runtime** named where the runtime is the real constraint, and with PAN's own release history left as history. Three parts are worth recording:

- **Anti-drift lint:** new `tests/model-version-drift.test.cjs`, built in the same shape as `tests/shipped-content-prefix.test.cjs` (the lint that permanently closed the path-prefix class). It fails if a version-pinned Claude model reference reappears in shipped content or live docs, rejects stale allowlist entries, guards against a broken or non-recursive walk, asserts each known drift shape is actually caught, and pins the generated SKILLS docs against staleness. Code is out of scope by design: `detectModelCapabilities` and `cost.cjs`'s rate table legitimately enumerate model ids.
- **A real code bug, fixed:** `detectModelCapabilities` (`bin/install-lib.cjs`) is a hand-maintained substring table whose only consumer is the installer's advisory post-install notice (`bin/install.js`, suppressed by `--skip-warnings`); it gates no feature. Any Claude id the table did not recognize fell through to the all-false `unknown` result, at which point the installer told the user their flagship model "lacks 1M context / extended thinking" — false, and worst on the newest models. The sweep added the missing `opus-5`/`sonnet-5` branches and then a family-level fallback. A follow-up fixed the fallback's two real defects: the threshold was major-only *and* the greedy legacy branches (`n.includes('opus-4')`) intercepted every generation-4 point release before the fallback could see it, so `claude-opus-4-9` still returned `has_1m_ctx: false`. The current rule compares a **single parsed generation key against the newest LEGACY release per family** (`opus`/`sonnet`/`haiku` 4.5): anything strictly newer is a forward release and inherits that family's modern profile; the legacy branches are bounded by the same derived flag, so no id can fall into the `unknown` hole by construction. The key is an integer (`major * 1000 + point`), because `Number('4.10')` would have sorted Opus 4.10 *below* 4.5 — a latent bug in the first attempt. A date suffix is not read as a point release (`claude-opus-4-20250514` stays legacy). Legacy mappings are untouched (Opus/Sonnet 4.0–4.5 at 200K, Haiku without thinking, Claude 3.x), non-Claude vendors are deliberately not guessed at, and forward-compat cases were added to `tests/installer-functions.test.cjs`.
- **Context-window phrasing:** "a fresh 200K context window" became "a fresh context window" in prose. PAN's own `CONTEXT_WINDOW` constant (200000, consumed only by `context-budget.cjs` and `commands.cjs`) is a planning assumption of PAN's, not a reading of any model's real window; the place it is still documented as a number *and explained as PAN's own constant* is the `context-budget` section of `docs/CLI-REFERENCE.md`. Two tracked branding drafts under `docs/branding/` also still carry the bare number; they are marketing drafts, deliberately retained by that directory's own keep-list, and were left out of the sweep's scope.

### (c) Correction pass — 3 High false claims the sweep introduced

De-versioning over-corrected. Three claims were false rather than merely imprecise, and all three were fixed:

1. **An invented capability probe.** The sweep's prose implied PAN detects a model's real capabilities at install time. It does not: `detectModelCapabilities` is a hardcoded substring table with a family fallback, feeding one advisory warning. The correction says so explicitly at the function and in the lint's header. The opposite over-claim was also avoided — "no module inspects the model name" would be false, because `cost.cjs`'s `resolveRate` does read the model string to pick a rate (`configRates[model]` → family-prefix → tier fallback).
2. **A false future-model promise** — text implying PAN automatically handles any future model. The fallback covers only known Claude families at a newer generation, and only for the advisory notice; an unrecognized vendor id still yields `unknown`. Rewritten to promise exactly that and no more.
3. **An invented model gate for `--hierarchical`**, asserted in five documents. Ground truth: no model gate exists anywhere. `grep -rn hierarchical` over `bin/`, `pan-wizard-core/bin/` and `hooks/` hits only two comments in `bus.cjs`; `agents/pan-conductor.md` ships no `model:` frontmatter at all (only `pan-hardener`, `pan-meta-reviewer` and `pan-reviewer` carry one, all `model: opus`); and under the default profile the conductor inherits the session model. The real constraint is the **runtime** — native sub-agent spawning, i.e. Claude Code. All five were rewritten to runtime-only phrasing, matching `exec-phase.md` and `docs/ARCHITECTURE.md`.

The exact wording the sweep introduced is not recoverable from version control: both the sweep and its correction are uncommitted, so this record describes the claims, not the strings.
